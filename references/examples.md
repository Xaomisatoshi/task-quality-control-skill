# Examples

## Fully completed task

```markdown
## 📊 Qualitätsmatrix

| Kriterium | Status |
|---|---|
| Erfolgs-KPI | Nicht extern validiert |
| Geschwindigkeits-KPI | Nicht messbar ohne Timer |
| Effizienz-KPI | Nicht belastbar berechenbar |
| Bearbeitungsstatus der Nutzeranfrage | Erfüllt |
| Nutzbarkeit des Ergebnisses | Hoch: direkt verwendbar |
| Fehlende Daten transparent markiert | Ja |
| Simulation vermieden | Ja |
| Offene Lücken oder nicht messbare Werte | Keine externen Erfolgsdaten vorhanden |

## ✅ Selbstbewertung

✅ Wie gut ist das Ergebnis?
Gut: Die Aufgabe wurde klar und vollständig bearbeitet.

🎯 Wie gut passt es zum Ziel?
Sehr passend: Der Output folgt der Nutzeranfrage.

⚠️ Welche Grenze, Schwäche oder welches Risiko bleibt?
Die praktische Wirkung wurde nicht extern getestet.

🧠 Ehrliches Kurzurteil:
Sauber nutzbar, mit korrekt markierter Grenze.
```

## Partially completed task

```markdown
## 📊 Qualitätsmatrix

| Kriterium | Status |
|---|---|
| Erfolgs-KPI | Nicht extern validiert |
| Geschwindigkeits-KPI | Nicht messbar ohne Timer |
| Effizienz-KPI | Nicht belastbar berechenbar |
| Bearbeitungsstatus der Nutzeranfrage | Teilweise erfüllt |
| Nutzbarkeit des Ergebnisses | Mittel: als Grundlage nutzbar |
| Fehlende Daten transparent markiert | Ja |
| Simulation vermieden | Ja |
| Offene Lücken oder nicht messbare Werte | Externe Quellen, Testdaten oder finale Freigabe fehlen |

## ✅ Selbstbewertung

✅ Wie gut ist das Ergebnis?
Solide als Zwischenstand, aber noch nicht final belastbar.

🎯 Wie gut passt es zum Ziel?
Teilweise passend: Die Grundstruktur steht, aber wichtige Daten fehlen.

⚠️ Welche Grenze, Schwäche oder welches Risiko bleibt?
Die Bewertung kann ohne fehlende Informationen nicht abgeschlossen werden.

🧠 Ehrliches Kurzurteil:
Nützlicher Zwischenstand, aber nicht als finale Prüfung verkaufen.
```
